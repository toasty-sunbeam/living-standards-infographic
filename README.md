# Living Standards Infographic Builder

A small web app for building "The Four Levels" infographic — Rosling's four
income levels, rendered as a census-form-style pictogram of who's alive today
and who has died at each level, plus a living-standards matrix (water,
cooking, eating, sleeping, transportation, light, data). Everything is
controlled from a sidebar and rendered live as an actual `<svg>`, which you
can export as a standalone `.svg` file.

## Running it

```sh
npm install
npm run dev
```

Open the printed local URL. Edit text/colors/scale in the left panel; click
**Export SVG** to download the current render as a self-contained SVG file.

## Data

Population figures (`src/data/levels.ts`) and the living-standards row
definitions (`src/data/standardsRows.ts`) come from the `abundance-data`
package — see `data/10_levels_living_and_dead.csv` /
`data/bundle.json → levels_living_and_dead` for the source numbers, and
`design/thesis-and-icons.md` / `design/icon-sourcing.md` for the intended
final icon set (Pinhead Map Icons, CC0). That package isn't vendored into
this repo; only the figures and row structure derived from it are.

## Swapping in real icons

The living-standards icons (water, cooking, eating, sleeping,
transportation, light, data — 4 levels each) are **placeholders**: a dashed
box with a level-progress dial, generated by
`scripts/generate-placeholder-icons.mjs`. To use real artwork, just
overwrite the matching file in `src/icons/standards/`, e.g.
`src/icons/standards/water-3.svg` — same filename, same `viewBox="0 0 24
24"`. Nothing else needs to change: the app loads every SVG in that folder
automatically via `import.meta.glob` (`src/icons/loadIcons.ts`), and Vite's
dev server picks up the change immediately.

- `src/icons/standards/data-1.svg` intentionally doesn't exist — "nothing"
  is the datum for Data at Level 1 (see `blankLevels` in
  `src/data/standardsRows.ts`). Don't add a file for it.
- `src/icons/people/alive.svg` and `dead.svg` are the population-pictogram
  icons; swap these the same way (e.g. for a headstone icon for "dead").
- Icons should be single-color silhouettes/line art using `currentColor`
  (`fill="currentColor"` or `stroke="currentColor"`) so the app's color
  controls apply. Presentation attributes set on the icon's root `<svg>`
  (fill, stroke, stroke-width, ...) are carried over and inherited by its
  children when the icon is embedded, same as in the standalone file.

Re-run `node scripts/generate-placeholder-icons.mjs` any time to regenerate
missing placeholders — it never overwrites a file that isn't itself a
placeholder (checked via a `data-placeholder="true"` marker attribute), so
real icons you've dropped in are safe.

## How the export works

`InfographicSvg` (`src/components/InfographicSvg.tsx`) computes the entire
layout in plain JS/SVG coordinates — no CSS layout, no `<foreignObject>` —
so the exact DOM node on screen *is* the file you download
(`src/lib/exportSvg.ts` just serializes it). Icons are inlined as
`<symbol>`/`<use>`, so the exported file has no external dependencies other
than a best-effort Google Fonts `@import` (falls back to system fonts if
unavailable).
